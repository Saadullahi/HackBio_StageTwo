## High-Level Dataset Overview — PneumoniaMNIST

Task: Classify images as

0 = Normal

1 = Pneumonia

Size

Train: 4,708

Validation: 524

Test: 624

Total 5,856 images.

Image format

Gray-scale

28×28 pixels (MNIST-like)

No clinical preprocessing required.

## Step 5: Train & Evaluate Random Forest Classifier without & with Class Weights






















### Evaluation Metrics Selection




For a medical diagnostic task like Pneumonia detection, especially with an imbalanced dataset, selecting the right evaluation metrics is crucial. The key relevant evaluation metrics for this specific task include:






Accuracy






Confusion Matrix (True Positives, True Negatives, False Positives, False Negatives)






Recall (Sensitivity or True Positive Rate)






Precision (Positive Predictive Value)






F1-Score






ROC AUC (Receiver Operating Characteristic - Area Under the Curve)






AUPRC (Area Under the Precision-Recall Curve)






In summary, for the PneumoniaMNIST dataset






Recall for the 'Pneumonia' class is critical to avoid missing actual cases.






Precision for the 'Pneumonia' class is important to avoid misdiagnosing healthy patients.






Accuracy gives a general overview but should be interpreted with caution due to class imbalance.






AUPRC provides the most comprehensive and reliable single metric for assessing the model's ability to handle the minority 'Pneumonia' class effectively, balancing both precision and recall, and is generally preferred over ROC AUC for such imbalanced medical tasks.

Comparison and Comments




Overall Accuracy: The model without class weights achieved a higher overall accuracy (0.8526 vs. 0.8237).






Recall for 'Normal' Class: the initial goal was to improve recall for the 'Normal' class. However, contrary to expectations, the recall for 'Normal' decreased from 0.65 to 0.57 when class_weight='balanced' was applied. This means the model with class weights was less effective at identifying actual 'Normal' cases.






Precision for 'Normal' Class: Both models showed high precision for 'Normal', but it slightly decreased with class weights (0.94 to 0.93).






Recall for 'Pneumonia' Class: Both models maintained very high recall for 'Pneumonia' (0.98 vs. 0.97), indicating they are still excellent at detecting the disease.






Precision for 'Pneumonia' Class: The precision for 'Pneumonia' also slightly decreased with class weights (0.82 to 0.79).






In this specific case, using class_weight='balanced' did not yield the desired improvement for the 'Normal' class recall. Instead, it led to a slight degradation across most metrics, including the overall accuracy and the recall for 'Normal'. This sometimes happens because simply balancing class weights can shift the decision boundary in a way that doesn't necessarily optimize for all metrics or the specific minority class in complex datasets. It suggests that this simple balancing technique might not be the most effective approach for this particular dataset to address the 'Normal' class recall. Other strategies, like different forms of resampling or more advanced hyperparameter tuning, might be considered.
























##Step 6: Exploring Alternative Techniques for Class Imbalance


### Technique 1: SMOTE (Synthetic Minority Over-sampling Technique)




SMOTE works by creating synthetic samples from the minority class. It selects a sample from the minority class and then finds its k-nearest neighbors. Synthetic samples are generated by taking the difference between the selected sample and its neighbors, multiplying by a random number between 0 and 1, and adding it to the selected sample. This effectively creates new, similar samples in the feature space.

### Technique 2: Undersampling (RandomUnderSampler)




Undersampling aims to balance class distribution by reducing the number of samples in the majority class. Random Undersampling randomly removes instances from the majority class until the desired ratio is met. This can help address imbalance but might lead to a loss of potentially useful information from the removed samples.

### Technique III: Hyperparameter Tuning for Random Forest Classifier (with Undersampled Data)




Use of RandomizedSearchCV to search for the best hyperparameters for the Random Forest Classifier trained on the undersampled data.






This approach is computationally less expensive than GridSearchCV while still effective in finding good parameter combinations.




















In [29]:






from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import randint

# Define the parameter distribution for RandomizedSearchCV
param_dist = {
    'n_estimators': randint(50, 200),  # Number of trees in the forest
    'max_features': ['sqrt', 'log2', None], # Number of features to consider at every split
    'max_depth': randint(10, 50),       # Maximum number of levels in tree
    'min_samples_split': randint(2, 20),# Minimum number of samples required to split a node
    'min_samples_leaf': randint(1, 10), # Minimum number of samples required at each leaf node
    'bootstrap': [True, False]          # Method for sampling data points (with or without replacement)
}

# Initialize a fresh Random Forest Classifier for tuning
rf = RandomForestClassifier(random_state=42, n_jobs=-1)

# Initialize RandomizedSearchCV
# We'll optimize for 'recall_macro' to ensure good recall for both classes.
random_search = RandomizedSearchCV(estimator=rf,
                                   param_distributions=param_dist,
                                   n_iter=50, # Number of parameter settings that are sampled
                                   cv=5,      # 5-fold cross-validation
                                   scoring='recall_macro', # Metric to optimize
                                   random_state=42,
                                   n_jobs=-1,
                                   verbose=2)

print("Starting RandomizedSearchCV for hyperparameter tuning...")
# Fit RandomizedSearchCV to the undersampled training data
random_search.fit(X_train_rus, y_train_rus)
print("RandomizedSearchCV complete.")

ROC AUC stands for Receiver Operating Characteristic - Area Under the Curve. ### ROC AUC vs. AUPRC for Imbalanced Datasets




I have calculated both the ROC AUC (0.9495) and the AUPRC (0.96) for the tuned Random Forest model on the PneumoniaMNIST dataset. While both are powerful metrics for evaluating classification models, they provide different insights, especially in the context of imbalanced datasets.




### 1. ROC AUC (Receiver Operating Characteristic - Area Under the Curve)


    

  • What it measures: The ROC curve plots the True Positive Rate (TPR, also known as Recall or Sensitivity) against the False Positive Rate (FPR, or 1 - Specificity) at various classification thresholds. The AUC (Area Under the Curve) quantifies the overall ability of a model to distinguish between classes across all possible thresholds.
    • 

  • Interpretation: A higher ROC AUC score indicates a better ability of the model to separate positive from negative classes. An AUC of 0.5 suggests random guessing, while 1.0 is a perfect classifier.
    • 

  • Strengths: It is generally robust to class imbalance, meaning it doesn't penalize models for high False Positives if the False Negatives are also high, or vice-versa, for both classes. It gives an overall assessment of a classifier's performance.
    • 

  • Limitations for Imbalanced Datasets: While robust, ROC curves can sometimes be misleading in highly imbalanced datasets. If the negative class (Normal) is significantly larger, a model can still achieve a high ROC AUC by performing well on the majority class, even if its performance on the minority class (Pneumonia) is poor.
    • 



### 2. AUPRC (Area Under the Precision-Recall Curve)


    

  • What it measures: The Precision-Recall curve plots Precision (the proportion of positive identifications that were actually correct) against Recall (the proportion of actual positives that were identified correctly) at various classification thresholds. The AUPRC quantifies the overall performance, specifically focusing on the positive class.
    • 

  • Interpretation: A higher AUPRC indicates that the model is better at retrieving positive instances (high recall) while also making sure that most of the retrieved instances are actually positive (high precision). An AUPRC close to 1.0 is ideal.
    • 

  • Strengths: AUPRC is particularly informative and preferred for imbalanced datasets, where the positive class is rare (as is often the case with disease detection, like Pneumonia). It focuses on the model's ability to correctly identify the minority class. A model performing poorly on the minority class will have a low AUPRC, even if it performs well on the majority class.
    • 

  • Limitations: It primarily evaluates performance on the positive class.
    • 



### Comparison for PneumoniaMNIST




In the context of the PneumoniaMNIST dataset, which is imbalanced (more Pneumonia cases than Normal in the training set after undersampling, but still an imbalance initially), correctly identifying Pneumonia (the positive class) is often the primary concern. Therefore:




    

  • The ROC AUC of 0.9495 shows that the model has excellent overall discriminatory power between 'Normal' and 'Pneumonia' cases.
    • 

  • The AUPRC of 0.96 is an even stronger indicator, specifically highlighting the model's exceptional performance in identifying 'Pneumonia' cases correctly, with both high precision and high recall. This is particularly reassuring given the class imbalance.
    • 





In Summary: For a medical diagnosis task like Pneumonia detection, where missing a positive case (False Negative) can have serious consequences, and incorrectly diagnosing a healthy patient (False Positive) can lead to unnecessary treatment, AUPRC often provides a more truthful and direct measure of a model's effectiveness in real-world scenarios, especially when dealing with imbalanced data.






The high AUPRC suggests that the tuning strategies have successfully optimized the model for the critical task of accurately identifying Pneumonia.
